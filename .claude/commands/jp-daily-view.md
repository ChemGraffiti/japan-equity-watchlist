# 日次相場観コメント / Daily Market View

CLAUDE.md のルール①〜④（日英併記・主観客観の明示・専門用語注釈・引用リンク化）に従い、今日の日本株市場がどう動くかをまとめる。
Following Rules ①-④ in CLAUDE.md (bilingual, subjective/objective split, term annotation, linkable citations), summarize how today's Japanese stock market is likely to move.

実行時点の日付を yyyy-MM-dd 形式で求め、これを {date} とする。

## 実行上の制約 / Execution constraint

**2026-08-01決定: 日本113銘柄すべての日次個別更新を廃止し、各業種の代表3銘柄（計33銘柄、`SECTOR_REPS`）のみを毎日調査する方式に変更した（使用率削減のため。詳細はステップ2参照）。これにより日本株部分の調査量は113→33銘柄（約71%減）となり、日本株だけなら1〜2バッチで十分・タイムボックスも実質不要になった。** 一方、米国・中国・韓国（朝ルーティーンのみ、合計US99+CN92+KR77≈268銘柄）は今回の対象外で、従来どおり調査量が大きいため、以下の制約は**米国・中国・韓国部分にのみ**引き続き適用する。

**同時に起動する調査用サブエージェントは合計8〜10個までとし、1エージェントあたりの担当ティッカー数を約30〜50件に収めること。** WebSearchはセッション全体（メイン＋全サブエージェント）で予算(200回程度)を共有している。2026-07-27に3回連続で失敗した経緯:
1. 16並列で起動しセッション予算を数分で枯渇させ失敗。
2. 「並列4〜6個までに統合」で再実行→JP+US+CN+KRを同じバッチに統合した結果、1エージェントあたりの調査量が単純合算で4倍(最大110件超)に膨れ上がり、3時間半ハング。
3. 「市場ごとに別バッチ(8〜10バッチ)＋タイムボックス」で再実行→ハングは解消したが、**JP113+US99+CN92+KR77≈381銘柄という調査総量自体がセッション予算(200回)を構造的に超えており**、予算切れで部分更新（32/113銘柄等）に終わった（詳細は`daily/2026-07-27_正午.md`参照）。日本株部分は2026-08-01の33銘柄化で軽くなったが、米国・中国・韓国268銘柄は依然重いため、この教訓は米国・中国・韓国部分に引き続き適用する。

**したがって、バッチの分け方だけでは解決しない。以下を必ず守ること:**
- **正午実行時はUS_PRICE/CN_PRICE/KR_PRICEの調査をすべて省略し、日本の代表33銘柄のみ更新する**（2026-07-28決定：米国・中国・韓国は1日1回・朝のみの更新に統一。米国は正午時点で未開場のため調査が無駄になる、中国・韓国は朝と昼で二重調査すると予算を圧迫し正午側のハング・異常値棄却の原因になっていたため。ステップ2・4.5・4.6参照）。
- **可能な限り、1銘柄1検索ではなく複数銘柄をまとめて取得できる一覧ページ（証券会社のポートフォリオ機能、株価一覧ページ、指数構成銘柄一覧等）をWebFetchで取得し、1回のリクエストで複数銘柄の値を読み取ることで検索回数を削減する。**
- 上記を行ってもなお全銘柄を予算内でカバーしきれない場合は、**タイムボックスに従い部分更新で構わない**（未取得銘柄は前回値を維持し、`AS_OF`に「一部混在」等と明記。無理に全銘柄分の検索を続けて予算超過・ハングを起こすよりよい）。

**タイムボックス（重要・二重の安全策）**: 調査開始からおおむね20〜25分を目安とし、それを過ぎたら現時点で判明している情報だけでレポートを完成させて保存・コミットすること。全銘柄・全項目が埋まるまで無限に調査を続けないこと。未取得の項目は「不明」「要確認」と明記すればよい。**「完全なレポートを遅く出す」より「不完全でも早く安全に保存する」ことを優先する。**

## ステップ / Steps

1. **ベースデータの確認 / Load baseline data**
   - `fundamentals/` 内で最新の `watchlist_fundamentals_*.md`（マスターDB）を探して読み込む。存在しない、または1ヶ月以上前の日付の場合は、コメント中で「データが古い可能性がある」旨を明記する（フル再調査はユーザーに別途確認してから行う。日次コマンド内では自動でフル再調査は行わない）。
   - [../決算日/決算発表予定一覧_2026.md](../../決算日/決算発表予定一覧_2026.md) およびマスターDBの「次回決算発表予定日」列を確認し、{date}から向こう1週間以内に決算発表が予定されているウォッチリスト銘柄を洗い出す。

2. **ダッシュボードの株価を更新 / Refresh the dashboard's DAILY object**
   **2026-08-01以降、日本113銘柄全数の調査は行わない。** [japan_equity_sector_map_v2.html](../japan_equity_sector_map_v2.html) 内の`<script>`にある`SECTOR_REPS`オブジェクト（11業種×代表3銘柄＝計33銘柄）のコードのみについて、直近取引日の終値と前日比%を軽量調査する。33件と少ないため1〜2バッチで十分（並列エージェント不要な場合も多い。Yahoo!ファイナンス優先、kabutan.jpは403のため不使用、代替はirbank.net/nikkei.com/kabuyoho.ifis.co.jp）。取得した値で`<script>`内の`DAILY`オブジェクトの**該当33銘柄分のエントリのみ**を新しい`[株価,前日比%]`の値に置き換える（他の80銘柄のエントリは触らない＝前回値のまま据え置く。これは意図的な仕様で、113銘柄一覧テーブル自体はサイトに残るが日次更新はしないというユーザー承認済みの方針）。あわせて`AS_OF`の日付も更新する。
   - **例外（イベント駆動の追加更新）**: ステップ1で洗い出した「本日決算発表等の重大イベントがある銘柄」が`SECTOR_REPS`に含まれていない場合でも、その銘柄は個別に追加調査し、`DAILY`エントリを更新してよい（むしろ推奨。イベントで話題になる銘柄の鮮度を保つため）。
   - `BASE`オブジェクトやCSS・HTML本体（テーブル行・nav）は**触らない**（データ駆動設計のため、DAILYの差し替えだけで表・ミニチャート・セクターヒートマップが自動更新される）。
   - 決算発表・株式分割・上場廃止など個別銘柄の「事案」があった場合のみ、該当コードの`BASE`エントリ（p/per/pbr/cr/dec等）も更新する。
   - あわせて🇯🇵/🇺🇸/🇨🇳/🇰🇷表示モード切替用に、`USBASE`/`CNBASE`/`KRBASE`のキー(JPコード)に対応する米国・中国・韓国銘柄の株価も軽量調査し、`<script>`内`US_PRICE`/`CN_PRICE`/`KR_PRICE`オブジェクトを新しい値に**すべて置き換える**（こちらは2026-08-01の変更対象外、引き続き全銘柄調査）。`USBASE`/`CNBASE`/`KRBASE`(ティッカー・社名・PER/PBR・決算日・関係性・選定理由)は**触らない**（PER/PBRは各PRICEオブジェクトとの比率で自動換算される）。**あわせて同じページから前日比%も読み取り、`US_CHG`/`CN_CHG`/`KR_CHG`オブジェクト（コード→前日比%の数値、2026-08-04追加）に記載する。**多くの情報源では価格の隣に前日比%が表示されているため、追加の検索は基本的に不要（同じページから2つの数値を拾うだけ）。`US_PRICE`/`CN_PRICE`等（現在値）はUSBASE.p等の起動時上書きによって前日比の再計算に使えない（常に0%になる）ため、`XX_CHG`が業種ヒートマップ・資金フロー分析の🇺🇸🇨🇳🇰🇷モードの唯一のデータ源になっている。前日比%が取得できなかった銘柄は`XX_CHG`にキーを追加しない（"該当なし"と同じ扱いで業種平均から自動的に除外される。0を書き込むと「変化なし」と誤って解釈されるため、未取得の場合は必ずキー自体を作らないこと）。米国はstockanalysis.com、中国・韓国はeastmoney.com/stockanalysis.com優先で取得する。「該当なし」判定でキーが存在しない銘柄は調査不要。**上記「実行上の制約」に従い、US/CN/KRは独立したバッチ（US用1〜2、CN用1〜2、KR用1〜2）として並列実行する（日本の1〜2バッチと合わせて合計4〜7バッチ程度）。可能な限り一覧ページのWebFetchで検索回数を節約すること。**
   - **正午前後（11:00〜14:00頃）に実行する場合は、US/CN/KRいずれも調査・更新を省略し、日本の代表33銘柄のみ更新する**（2026-07-28決定：米国・中国・韓国は1日1回・朝のみの更新とし、正午は日本国内銘柄の速報性を優先する。理由は(a)米国市場は正午時点で未開場のため朝と実質同じ値になり調査が無駄、(b)中国・韓国は朝と昼で二重に調査するとセッションのWebSearch予算(約200回)を圧迫し、それが原因でCN/KRデータが正午側で度々ハング・予算切れ・異常値棄却を起こしていたため。`USBASE`/`US_PRICE`/`CNBASE`/`CN_PRICE`/`KRBASE`/`KR_PRICE`は正午実行では一切触らず、前回(朝)の値のまま据え置く。この場合は日本の1バッチのみでよく、US/CN/KR用バッチは不要）。
   - 更新後、Edgeヘッドレスでスクリーンショットを撮って表示崩れがないか確認する。

3. **当日の市況を調査 / Research today's market conditions**
   WebSearchで以下を調べる（出典URLを必ず控える）:
   - 前日までの日経平均・TOPIXの終値と当日の日経平均先物（CME/大阪取引所）の動き
   - 米国株市場（S&P500・NASDAQ・ダウ）の直近の終値・値動きとその主因
   - ドル円などの為替動向
   - 当日または直近の重要な経済指標・金融政策イベント（日銀・FRB等）。**{date}から向こう7日以内の日程を確認する際は、以下の「原則毎月同じ頃に発表される」定例指標を必ずチェックリストとして確認すること**（過去に「7日にCPIがあるはずでは」「経済指標が2件しかないのはおかしい」とユーザーから指摘があり、この確認漏れが原因だった）: 米ISM製造業景況指数(月初営業日)／米ISM非製造業(サービス業)景況指数(月初から3営業日目頃)／米雇用統計(月初の金曜、非農業部門雇用者数)／米CPI(月央、10〜13日頃)／中国財新(Caixin/RatingDog)製造業PMI(月初営業日)／FOMC・日銀金融政策決定会合(いずれも不定期、日程は都度要確認)。該当月に該当日程が実施日から7日以内に入っていないか確認し、入っていれば出典付きでEVENTSに追加する。
   - 地政学リスクなど、日本株全体に影響しうるニュース
   - 中国の景気・消費・当局の政策動向（インバウンド関連銘柄への影響が大きいため）
   - 韓国のKOSPI・サムスン電子・SKハイニックスの動向（半導体セクターが38銘柄とウォッチリスト最大のため、連れ高・連れ安の影響が大きい）

3.5. **世界情勢サマリーの更新 / Update the World Affairs cards**
   [japan_equity_sector_map_v2.html](../japan_equity_sector_map_v2.html) の `<script>` 内 `WORLD` オブジェクト（`japan`/`us`/`china`/`korea`の4地域、必要なら追加可）を、ステップ3の調査結果に基づいて更新する。各地域について:
   - `summary`（日本語）/`en`（英語、簡潔に）: 当日の状況を2〜3文で
   - `score`: 日本株への影響度を **-2（強い逆風）〜+2（強い追い風）** で判定（主観的判断だが、根拠は`summary`に書いた客観情報に基づくこと）
   - `asOf`: 情報の基準日
   - `source`: 主要な出典URL（あれば）
   これにより、ページ上部の世界情勢カードの色（赤=追い風、緑=逆風）が自動更新される。旧「一週間の投資情報まとめ」プロジェクトで週次のみ行っていた世界情勢分析を、この日次カードとして統合したもの。

4. **ウォッチリストとの紐付け / Tie back to the watchlist**
   - ステップ1で洗い出した決算発表予定銘柄について、直近の材料・注目ポイントを一言添える。
   - ステップ2で更新した前日比%を踏まえ、ステップ3の市況ニュースがウォッチリストのどのセクター・銘柄に特に影響しそうかを、[japan_equity_sector_map_v2.html](../japan_equity_sector_map_v2.html) の11分類（ヒートマップで可視化済み）に照らして紐付ける。
   - 個別に大きなニュース（決算・M&A・規制・事故等）が出ている銘柄があれば、WebSearchで補足調査し追記する。
   - **ステップ3で拾った各ニュース項目について、関連するウォッチリスト銘柄（証券コード・銘柄名）を特定する。** 直接的な当事者銘柄だけでなく、同業種・サプライチェーン上の関連銘柄（例: 原油高→INPEX/ENEOS、米長期金利上昇→メガバンク3行、半導体安→東京エレクトロン等の半導体セクション）も拾う。関連銘柄がない場合は無理に紐付けず「関連銘柄なし」と明記する。

4.5. **資金フロー分析 / Capital flow analysis**
   業種別ランキング自体は`japan_equity_sector_map_v2.html`の`renderFlow()`関数が自動計算するため、日次ルーティーンがランキングの数値を手で書く必要はない。**2026-08-01以降、日本(JPモード)の業種平均は113銘柄全数ではなく`SECTOR_REPS`（各業種の代表3銘柄、計33銘柄）のサンプルに基づく**（ステップ2で更新した`DAILY`から自動計算）。表示も「値上がりトップ3業種」「値下がりトップ3業種」の計6業種に絞られている（旧来の11業種全表示から変更済み）。米国・中国・韓国モードは引き続き全対応銘柄（`XX_PRICE`/`XXBASE`）の平均のまま（今回の変更対象外）。日次ルーティーンが書くのは**主観コメントのみ**：
   - `japan_equity_sector_map_v2.html`内の`const FLOW = {...}`オブジェクトの`jp`キー（正午実行かつ米国・中国・韓国のデータを更新した場合は`us`/`cn`/`kr`キーも）を編集し、`{subj:"...", asOf:"{date}終値"}`の形で「値上がりトップ3業種へ資金流入・値下がりトップ3業種から流出している可能性がある」という仮説とステップ3の市況ニュースとの関連付けを記述する（断定を避け「〜の可能性がある」と明記。JPは代表3銘柄のサンプルに基づく参考値である旨に触れること）。既存のキーは日付ごとに上書きしてよい（過去分は`daily/{date}.md`に残るため）。
   - `daily/{date}.md`（または`daily/{date}_正午.md`）にも、客観の値上がり/値下がりトップ3業種（表形式。ダッシュボードの`renderFlow()`と同じロジック＝`SECTOR_REPS`銘柄の前日比%単純平均で算出）と同じ主観コメントを記載する。
   - **正午実行時、米国・中国・韓国のデータを更新していない場合はFLOWの`us`/`cn`/`kr`キーは触らず、`daily/{date}_正午.md`側にも「米国・中国・韓国の資金フロー分析は本日朝の更新分を参照」と一言添えるのみでよい。**

4.6. **本日の注目銘柄トップ3 / Today's Top 3 stocks to watch**
   ウォッチリスト113銘柄から、前日比の大きさ・出来高・個別ニュース材料・決算間近か等を総合して「今日着目すべき銘柄トップ3」を選ぶ。**2026-08-01以降、日本113銘柄全数の前日比は把握できないため、選定候補プールは実質的に「`SECTOR_REPS`の33銘柄の動き」＋「ステップ1で洗い出した本日決算等イベントのある銘柄」＋「その他ステップ3で個別に材料が見つかった銘柄」になる。無理に113銘柄全数から選ぼうとせず、この範囲で妥当な3銘柄を選べばよい。**
   - `japan_equity_sector_map_v2.html`内の`const PICKS = {...}`オブジェクトの`jp`キー（正午実行かつ米国・中国・韓国のデータを更新した場合は`us`/`cn`/`kr`キーも）を、`{code, name, en, chg, obj, subj, asOf}`の配列3件で**上書き**する。`obj`（客観：株価・前日比%・PER/PBR・関連ニュースと出典URL、HTMLの`<a>`タグで出典リンク可）と`subj`（主観：なぜ注目すべきか、今後の値動きの見立て。断定を避ける）を分けて記載する。
   - 併せて`daily/{date}.md`（または`daily/{date}_正午.md`）にも同内容を客観/主観形式で記載する。
   - **同様に、対応する米国銘柄(`USBASE`)・中国銘柄(`CNBASE`)・韓国銘柄(`KRBASE`)の中からもそれぞれトップ3を選定し、`PICKS.us`/`PICKS.cn`/`PICKS.kr`と`daily/{date}.md`の両方に、同じ客観/主観形式で記載する**（合計 日本3＋米国3＋中国3＋韓国3 の12銘柄）。対応銘柄自体が存在しない（該当なし）銘柄しか候補にならない場合は、その旨を明記して次点を選ぶ。
   - **正午実行時は米国・中国・韓国のトップ3選定を省略する**（US/CN/KRのデータは朝から更新していないため、当日の値動きに基づく選定ができない）。`PICKS.us`/`cn`/`kr`は前回(朝)の値のまま触らない。日本(`PICKS.jp`)のみ更新すればよい（ダッシュボードは`PICKS`に該当モードのデータがない場合、自動的に日本のデータにフォールバック表示する）。
   - 更新後、Edgeヘッドレスでスクリーンショットを撮り、「📊 資金フロー分析＆本日の注目銘柄」セクションが正しく表示されているか確認する。

4.7. **今後7日間のイベントカレンダー / 7-day event calendar（1日1回・朝のみ更新）**
   `japan_equity_sector_map_v2.html`内の`const EVENTS = {...}`オブジェクトを、{date}から7日後（同じ曜日）までの範囲を対象に**全面的に書き換える**。
   - ステップ1で洗い出した「{date}から向こう1週間以内に決算発表が予定されているウォッチリスト銘柄」を`{date:"yyyy-MM-dd", type:"earnings", code:"証券コード", name:"銘柄名", note:"確定/頃/未確認 等の確度"}`の形式で`items`配列に追加する。
   - ステップ3で調べた金融政策イベント・経済指標（日銀金融政策決定会合、FOMC、米国雇用統計、米国CPI等、{date}から7日以内に予定されているもの）を`{date:"yyyy-MM-dd", type:"macro", label:"イベント名", note:"確度や補足(あれば)"}`の形式で追加する。日付が確定できないイベントは無理に含めず、`note`に「日程未確定」等と明記するか、いっそ含めない判断でもよい。
   - 表示側(`renderEvents()`)が`asOf`から7日後までの範囲を自動でフィルタして表示するため、`items`には多少前後の日付が混ざっていても構わない。ただし`asOf`は必ず{date}に更新すること。
   - **正午実行時はこのステップを一切行わない**（1日1回で十分なため。前回=朝の内容をそのまま維持する）。
   - 更新後、Edgeヘッドレスでスクリーンショットを撮り、「📅 今後7日間のイベントカレンダー」セクションが正しく表示されているか確認する。

5. **主観/客観に分けてまとめる / Write the subjective/objective summary**
   以下の構成で、日本語・英語を併記して記述する:
   - **客観 (Objective)**: 前日までの市況データ、当日の先物・為替、決算発表予定、個別銘柄ニュース（すべて出典URL付き）。**各ニュース項目の末尾に「(関連銘柄: 8035 東京エレクトロン, 6857 アドバンテスト 等)」の形式で、ステップ4で特定した関連銘柄を必ず併記する。**
   - **主観 (Subjective)**: 上記を踏まえて、Claudeとして今日の相場がどう動きそうか、どのセクター・銘柄に注目すべきかの見解（推測であることを明示し、断定を避ける）
   - ステップ4.5「資金フロー分析」とステップ4.6「本日の注目銘柄トップ3」を、それぞれ独立したセクションとしてこのコメントに含める。

5.5. **午前中サマリー（正午前後に実行する場合のみ）/ Morning session recap (noon runs only)**
   実行時刻がおおむね11:00〜14:00（クラウドの正午ルーティーン、またはユーザーが昼前後に手動実行した場合）は、上記に加えて「午前中サマリー」セクションを追加する。
   - **客観 (Objective)**: 本日前場の日経平均・TOPIXの値動き（始値・前場引け値・値幅・出来高）と話題になった個別ニュース。中国（上海総合等）・韓国（KOSPI）の午前の値動きも記載する。米国市場はまだ開いていないため、直近の先物・時間外気配のみ言及し「取引時間外」と明記する。
